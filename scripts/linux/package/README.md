# Linux release packages

Build on amd64 Debian 13 with Swift 6.4 installed by swiftly, Docker and `testrun`:

```sh
scripts/linux/package/build-deb.sh
scripts/linux/package/build-appimage.sh
testrun dictum linux-package-install -- scripts/linux/package/test-install.sh
```

The version defaults to `MARKETING_VERSION` in the repository's `VERSION` file. A first argument
or the `VERSION` environment variable overrides it; `OUT` selects an artifact directory (default
`scripts/linux/package/out`). `VIZIER_BINARY` can supply an already built static
release. Assemblers run in Debian trixie with `dpkg-deb` and appimagetool. Nothing
is installed on the build host. Generated packages, inspection trees, dependency
reports and logs stay in the ignored output directory.

Swift 6.4's default swiftbuild backend fails to link static Foundation's C
symbols on the Debian 13 build host. The builders use the native SwiftPM backend with
`-c release --product vizier --static-swift-stdlib -j 8`. Native SwiftPM is
deprecated, so this workaround must be revisited when upgrading Swift. The host
has libcurl.so.4 but no development symlink; the builder creates a linker alias
inside `out/link-libs`, without changing host libraries. `VIZIER_BINARY` is
checked with `ldd` too: missing or dynamically linked Swift libraries fail.

## Runtime requirements

The verified Swift 6.4 release statically includes Swift, Foundation, Dispatch,
BlocksRuntime and ICU (including its data). There is no Swift toolchain or ICU
runtime package dependency. CPipe2 is a header shim.

ELF NEEDED: `libwayland-client.so.0`, `libsqlite3.so.0`, `libcurl.so.4`, `libm.so.6`, `libstdc++.so.6`,
`libgcc_s.so.1`, `libc.so.6`, `ld-linux-x86-64.so.2`. Desktop D-Bus additionally
loads `libsystemd.so.0` at runtime. TLS cloud engines need CA certificates.
The complete recursive linkage of the build host is recorded in `out/ldd.txt`;
`out/readelf.txt` records the ELF's direct dependencies and `$ORIGIN` RUNPATH.

The tested Debian package's Depends are:

```text
libc6 (>= 2.38), libcurl4t64 (>= 7.86.0) | libcurl4 (>= 7.86.0),
libgcc-s1 (>= 3.3.1), libsqlite3-0 (>= 3.7.14), libstdc++6 (>= 12),
libsystemd0, ca-certificates
```

These are generated by `dpkg-shlibdeps` plus the dlopen/certificate requirements.
libcurl 8.11+ is a Recommends, since an older compatible curl can still run batch
engines; doctor reports the live-engine limitation. Helper recommendations are
`pipewire-bin | pulseaudio-utils`, `libsecret-tools`, `xclip | wl-clipboard`,
`xdotool | wtype`, and `libnotify-bin`. Clean tests suppress Recommends to prove
Depends alone suffice for headless operation.

The AppImage contains the same static release, sounds, desktop entry, 256 px
PNG icon and license notices. AppRun resolves the bundled binary without changing
library or XDG environment variables. It relies on the host's libraries listed
above; it does not bundle distro libraries. appimagetool 1.9.1 and the type2
runtime are separately checksum-pinned. The runtime's upstream URL is mutable;
a changed asset fails verification until its pin is deliberately updated.

## Clean-install proof

`test-install.sh` pulls Debian trixie and Ubuntu 26.04 (falling back to 25.10 only
if the 26.04 image cannot be pulled). Apt installs the deb and its Depends plus
Python for the test harness. No host home, toolchain or local binaries are mounted.
Ubuntu's minimal-image dpkg exclusions are overridden for Vizier's documentation
and man page so the test can verify the shipped NOTICE and LICENSE.
A non-root user gets fresh config/data paths and a private 0700 runtime directory.

`smoke.py` checks version, doctor, daemon/status, toggle/start and toggle/stop,
the final transcript and the matching history row, and SIGTERM socket cleanup.
It generates a WAV sine wave in code, streams its PCM through a recorder process,
and uploads the resulting FLAC to a loopback Python server that validates an
`/inference` multipart POST and returns a synthetic phrase. No desktop means the
take is held with its text in history. On Debian the AppImage additionally runs
`--appimage-extract-and-run --version`, then its extracted AppRun completes the
same take; this avoids needing FUSE or repeatedly extracting on every status poll.

The dependency mutation removed curl and other ELF Depends from the package.
Lintian rejected the incomplete dependency declaration, and the clean-install
smoke test failed at version startup because libcurl.so.4 was missing. The
declaration was restored before the final green run.

## Integration follow-ups

- `vizier setup` currently installs a user service but no desktop entry. AppImage
  cannot install its desktop entry automatically. Setup must install
  `net.praxient.vizier.desktop` for portal registration, and use the persistent
  AppImage path for service startup rather than a temporary extraction path.
- This application build's doctor has no desktop check (setup has one). The test
  reports that absence explicitly; capture/server failures and no crash are proven.
- Lintian's remaining `hardening-no-relro` warning comes from the Swift-linked
  executable. The build requests RELRO and immediate binding, but this toolchain
  emits BIND_NOW without a GNU_RELRO segment. Appimagetool also warns that optional
  AppStream metadata is absent. Desktop portals and real audio remain unverified.
- These files are Linux packaging only. There are no macOS-visible source edits.

COSMIC support links libwayland-client into the Linux executable; `.deb` dependencies
are discovered by `dpkg-shlibdeps`. Source builds also need `libwayland-dev`.
AppImage hosts must supply the runtime library. See [COSMIC setup](../../../docs/linux.md#pop_os-cosmic).
